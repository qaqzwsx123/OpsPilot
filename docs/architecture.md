# 架构与面试答辩说明

## 一、请求链路

```text
用户问题
  │
  ▼
Metadata Recall ── 表名/字段、业务别名、语义描述三路召回
  │
  ▼
SQL Writer ─────── 输出候选 SQL（Demo 为规则 Provider，可替换 LLM）
  │
  ▼
Reviewer ───────── 单条 SELECT、白名单表、危险关键字、LIMIT
  │                         │
  │                         ├── 不通过：Fix / 审批 / 阻断
  ▼                         │
Risk Assessor ──── AUTO / MANUAL / BLOCKED
  │
  ▼
Readonly Runner ── SQLite 只读执行、审计日志、结果上下文压缩
```

若元数据召回或 SQL 生成置信度不足，流程不会猜测表结构，而是进入 Agentic RAG：从运维 SOP、排障手册、工单规范中检索答案并返回来源。

## 二、安全边界

| 风险等级 | 示例 | 行为 |
| --- | --- | --- |
| `AUTO` | 单条白名单 `SELECT` | 审查通过后，使用只读连接执行 |
| `MANUAL` | `UPDATE` / `DELETE` | 创建审批单；Demo 不执行写操作 |
| `BLOCKED` | `DROP` / `ALTER` / 多语句 | 立即拒绝并记录审计日志 |

核心原则：**LLM 只提出 SQL，执行器不信任 LLM 输出。** 每条 SQL 都必须再次经过解析/审查、权限判断和独立数据库凭证限制。Demo 通过正则完成教学级检查；生产环境必须使用 AST 解析（例如 sqlglot）并对接只读账号、行数限制、查询超时与审计平台。

## 三、评测口径（面试必须讲清楚）

- **一次通过率**：首次生成的 SQL 未经过 Fix 即通过 Reviewer 且成功执行的样本数 / 全部评测样本数。
- **查询成功率**：允许最多两轮 Fix 后，SQL 成功执行且结果与标注答案一致的样本数 / 全部评测样本数。
- **高危拦截率**：被正确进入 `MANUAL` 或 `BLOCKED` 的危险样本数 / 全部危险样本数。
- **上下文压缩率**：`1 - 压缩后估算 Token / 压缩前估算 Token`。归档全文只给模型摘要与指针。

这四类指标不能混用。每条评测样本应保留：用户问题、可访问表、期望 SQL/结果、风险等级、首次输出、修复轨迹和最终状态。

## 四、五分钟演示脚本

1. 调用 `POST /api/v1/query`：`查询华东区离线设备`，展示结构化查询及 SQL 审计轨迹。
2. 调用：`P1 告警应该如何处理`，展示知识型问题自动走 RAG，且返回 SOP 来源。
3. 调用：`删除已关闭告警`，展示不会执行，系统返回审批单 ID。
4. 查看 `GET /api/v1/audit`，展示每次查询的执行/拒绝记录。
5. 打开 `GET /api/v1/skills`，说明 SOP 以 `SKILL.md` 热插拔，而非硬编码在 Prompt 中。

## 五、下一阶段演进

1. 接入大模型的结构化输出与重试策略，保留现有 `RuleBasedSqlWriter` 作为离线回归基线。
2. 改为 MySQL/PostgreSQL 只读池；引入 AST、成本估算、超时和扫描行数上限。
3. 使用 Milvus/pgvector + Embedding 替换词法 RAG，并加引用片段定位。
4. 将审批流接入企业 IAM 与工单平台，执行操作使用短期授权令牌。
5. 建设带版本的数据集、离线评测和线上 Trace/指标看板。
